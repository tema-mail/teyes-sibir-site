# Прогноз статьи и сверка с фактом

Читать, когда ставишь прогноз новой статье, сверяешь факт или Артём спрашивает «сколько принесут статьи».

## Формула (гипотеза до первой сверки, записана 01.11.2026)

S – спрос главного запроса из плана: Вордстат, Новосибирск, в месяц, снят 11.10.2026.
Это широкое соответствие: в него вложены все хвосты, поэтому статья берёт только долю.

Показы статьи в первой десятке Яндекса считаются по ступеням, без скачков на границах:

- первые 200 спроса – половина (0,5);
- от 200 до 1000 – 0,3 от этой части;
- всё, что выше 1000, – 0,05: по общему слову («автозапуск», «магнитола андроид») нас не поставят, берём хвосты.

Показы = 0,5 × min(S, 200) + 0,3 × (min(S, 1000) − 200, если больше нуля) + 0,05 × (S − 1000, если больше нуля).
Так прогноз растёт вместе со спросом и не проваливается на 1000 (было до 01.11: доля 0,05 на весь спрос выше 1000 –
статья со спросом 1821 получала прогноз меньше, чем со спросом 829; нашёл независимый ревьюер).

- Визиты из Яндекса в месяц = показы × CTR. CTR = 0,04 (средняя позиция около 6).
- Google добавляет половину: визиты всего = визиты Яндекса × 1,5.
  Основание: за год 2 811 поисковых визитов из Google и около 5 229 из Яндекса (Метрика, срез 25.10.2026).
- Заявки = визиты × 0,05 для статьи «заявки» и × 0,01 для статьи «показы».
- Раскачка: первый месяц после публикации – 0 из Яндекса (обход после аварии октября 2026 стоит),
  из Google 30%; второй месяц – 60%; третий – 100%. Записываем прогноз третьего месяца.

Калибровка: модельная страница Honda Stepwgn, S около 320, дала 14 входов в месяц и 12% визитов с заявкой
(Метрика, поиск, 25.10.2025–24.10.2026). Формула на ней даёт 8,2 – то есть она осторожная в 1,7 раза для
хорошо стоящей коммерческой страницы. «Хороший сценарий» Артёму называть как прогноз × 2.

Посчитать прогноз по плану:

```bash
cd ~/Documents/teyes-sibir-site && python3 - <<'P'
import csv
def shows(s): return 0.5*min(s,200)+0.3*max(0,min(s,1000)-200)+0.05*max(0,s-1000)
for r in csv.DictReader(open('docs/stati-reestr.csv')):
    if r['ploshchadka']!='сайт': continue
    s=int(r['spros']); v=shows(s)*0.04*1.5; z=v*(0.05 if r['cel']=='заявки' else 0.01)
    print(r['nomer'], r['slug'], round(v,1), round(z,2))
P
```

## Сверка: 30, 60, 90 дней после публикации

Факт берёт `yandex-dannye`, задание ему одним сообщением на все статьи срока:

- Метрика, счётчик 99532918: входы с поиска на `/blog/<slug>` и визиты с целями заявки
  (форма 356775667, отправка контактов 377669331, телефон 357093507, мессенджер 357560733), период – с даты публикации.
- Вебмастер: есть ли адрес в поиске, показы и клики по адресу, запросы, по которым показывались.
- GSC: клики и показы по адресу.
- Дзен: цифры ведёт главред в `~/Sites/redakciya/zamery.csv`; второй раз не снимать, брать оттуда.

В реестр: `fakt_data`, `fakt_indeks` (да / нет / не собрано), `fakt_pokazy`, `fakt_vizity`, `fakt_zayavki`.
Пропуск – «не собрано: причина», не ноль.

## Пересчёт коэффициентов

После сверки 90 дней по 20 и более статьям: посчитать среднее «факт / прогноз» отдельно по группам
(Зима, Teyes, Камеры, Звук, Русификация, Комфорт) и заменить коэффициенты в этом файле, с датой
и числом статей, на которых посчитано. Старые значения не стирать – строкой «было».
